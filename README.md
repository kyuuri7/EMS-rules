# らぶぐらっ！EMS ルールサイト（再構築版）

## ✨ デザイン刷新メモ（黒×金の高級テーマ）

見た目を「黒 × 金」の高級感あるデザインに刷新しました。**新しくページを追加するときに特別な作業は不要**です。`content/*.md` に `#`（H1）・`##`（H2）・`###`（H3）で書くだけで、自動的に：

- 見出しが専用の上品なセリフ体（Cormorant Garamond × Shippori Mincho）になる
- `##` 見出しの左に金色（ダーク時）のバーが付き、スクロールで画面に入ると光る演出が入る
- 行間・余白も統一されたリズムで配置される

数字（価格・件数など）を欧文フォントで揃えたい時は、`<span class="num">1,280</span>` のように `num` クラスで囲むと、車リストの価格表示と同じ上品な数字フォントになります。

### 追加されたファイル

| ファイル | 用途 |
|---|---|
| `favicon.ico` / `favicon-*.png` / `apple-touch-icon.png` | ブラウザタブ・スマホホーム画面のアイコン（金の月桂樹エンブレム） |
| `og-image.png` | Discord・X（Twitter）などにURLを貼った時のリンクカード画像 |

### トップのヒーローセクション（統計カウンター）を編集したい場合

`index.html` の `<section class="hero" id="site-hero">` 内、`hero-stats` の中にある各数字は `data-target="42"` のように書かれています。この数字を書き換えるだけで、表示時に 0 から自動でカウントアップするようになります。ラベル文言（「稼働隊員数」など）もその下の `hero-stat-label` の文字を書き換えるだけでOKです。


元のサイトを見た目・機能ともにできるだけ忠実に再現した、GitHub Pages用の静的サイトです。
（検索ボックス／目次タブ／ライト・ダーク・システム連動テーマ／カード型レイアウト）

## フォルダの中身

```
ems-site/
├── index.html      … サイト本体（さわらなくてOK）
├── style.css        … デザイン（色を変えたい時だけさわる）
├── script.js         … 動作の仕組み（基本さわらなくてOK）
├── editor.html       … ページ作成用のプレビューツール（後述）
├── pages.json        … 目次（どのページがどの順番で並ぶか）
└── content/
    ├── ems-rule.md
    ├── mamoru-koto.md
    ├── ems-taiou.md
    ├── shoshin-kijun.md
    ├── kuruma-list.md
    └── hokokusho.md
```

**ページの中身は全部 `content/` の中の `.md`（Markdown）ファイルです。**
HTMLやCSSを触らなくても、この `.md` ファイルを編集するだけでページの内容を更新できます。

> ⚠️ 今回アップロードしていただいたPDFはページ数が多く、車リストのページは80%縮小印刷で
> 左右が見切れていたため、各ページの内容は**最初の部分だけ**を書き起こしてあります。
> 続きは `content/*.md` の中の `<!-- コメント -->` の場所に、同じ書式で追記してください。
> 「残りも書き起こして」と言っていただければ、続きの作業も手伝えます。

## 1. ページの中身を編集する（一番よく使う作業）

1. `content/` フォルダの中から編集したいファイルを開く（例: `ems-rule.md`）
2. 普通のメモ帳感覚で文章を書き換える。書式のルールは以下だけ覚えればOK：

   | やりたいこと | 書き方 |
   |---|---|
   | 大見出し | `# 見出し` |
   | 中見出し（区切り線つき） | `## 見出し` |
   | 小見出し | `### 見出し` |
   | 太字 | `**太字**` |
   | 箇条書き | 行頭に `- ` |
   | 引用（矢印付きの補足） | 行頭に `> ` |
   | 区切り線 | `---` だけの行 |
   | 画像 | `![説明](../images/ファイル名.png)` |
   | コードっぽい強調 | `` `/nametagmenu` `` |

3. 保存してGitHubにアップロードすれば、そのまま公開ページに反映されます。

## 2. 新しいページを追加する（`editor.html` を使うと簡単）

初心者の方でもテーマに合わせて簡単にページを作れるように、**プレビューツール**を用意しました。
サイトを公開すると、トップページの左側メニュー「ページ管理」から **🛠️ 新しいページを作る** ボタンで開けます。

1. `editor.html` を開く（サイトのサイドバーからワンクリック、または直接 `あなたのURL/editor.html`）
2. 上の欄でページID・タイトルを決め、その下にMarkdownで本文を書く（右側に**本番と同じ見た目**でリアルタイムにプレビューされます）
3. 「⬇️ .md ファイルをダウンロード」ボタンを押すと `ページID.md` がそのままダウンロードされるので、`content/` フォルダに入れる
4. 「📋 pages.json 用の1行をコピー」ボタンを押して、`pages.json` の配列の中に貼り付ける（他の行と同じように `,` で区切る）
5. `content/` フォルダと `pages.json` をGitHubにアップロードすれば、目次に新しいページが自動で追加されます

> `editor.html` は確認・作成用の道具なので、GitHubにアップロードしてもしなくても構いません
> （アップロードしておけば、サイト上からいつでもプレビューツールを開けて便利です）。

### 2-1. `editor.html` でできること（機能一覧）

- **📂 既存の.mdを読み込んで作り直す**：サイトのページ一覧から選ぶ（または `.md` ファイルを直接選ぶ）と、本文欄に中身が丸ごと読み込まれます。編集したあと「📋 本文（Markdown）をまるごとコピー」を押せば、GitHub上の該当 `.md` ファイルにそのまま貼り付けできます（ダウンロードして上書きアップロードでもOK）。
- **🔗 目次の自動生成**：本文中の `##` 見出し（や `<h2>`）を自動で検出し、ページ上部に貼れる目次ブロックを1クリックで挿入します。見出しにIDが無い場合は自動で付与されます。
- **パーツ挿入ボタン**：カーソルのある位置に、以下のパーツをワンクリックで挿入できます。
  - 見出し（H2 / H3 / サブ見出し）・区切り線
  - 強調ボックス（青＝情報／黄＝注意／赤＝禁止・危険）
  - **自由な枠**（青・緑・紫・オレンジ・ピンク・グレーから色を選んで挿入できる、タイトル＋本文の枠）
  - **自由カード**（アイコン・タイトル・説明文・タグを自由に書き換えられるカード。色も選べます）
  - 項目カード（field-card）・記入例ボックス・表（テーブル）・2カラム分割
  - 文字装飾（太字／箇条書き／引用／コード／画像）
- **🗑️ 内容をクリア**：本文を初期状態に戻せます。

新しく増えた「自由な枠」「自由カード」「2カラム分割」は `style.css` 側にも対応クラス（`.free-frame-*` / `.free-card-*` / `.split-cols`）を追加済みなので、`editor.html` 経由でなく直接 `.md` にHTMLを書いて使うことも可能です。

## 3. ページの並び順・削除

`pages.json` を開いて、上から順番に並んでいる行を並べ替える／削除するだけです。

```json
[
  { "id": "ems-rule",  "title": "EMSルール", "file": "content/ems-rule.md" },
  { "id": "mamoru-koto", "title": "EMSとして守ること", "file": "content/mamoru-koto.md" }
]
```

- `id` … ページのURL用の名前（半角英数とハイフンのみ、重複不可）
- `title` … 目次に表示される名前
- `file` … 対応する `.md` ファイルのパス

## 4. GitHub Pages でサイトを公開する手順（初めての方向け）

### ステップ1：GitHubアカウントを作る
1. https://github.com/ にアクセスし、右上の「Sign up」から無料アカウントを作成
2. メールアドレスの確認まで済ませる

### ステップ2：リポジトリ（サイト置き場）を作る
1. 右上の「＋」→「New repository」
2. Repository name に **`EMS-rules`** と入力
   - `username.github.io` のようなリポジトリ名にすると「そのアカウントのメインサイト」になり、
     `EMS-rules` のような通常の名前にすると `username.github.io/EMS-rules` というURLになります（ご希望の構成どおりです）
3. 「Public」を選択（GitHub Pagesの無料利用にはPublicが必要）
4. 「Create repository」をクリック

### ステップ3：ファイルをアップロードする
1. 作成したリポジトリのページで「Add file」→「Upload files」
2. この `ems-site` フォルダの中身（`index.html` や `content` フォルダなど）を**フォルダごとドラッグ＆ドロップ**
   - `content` フォルダはそのままドロップすればフォルダ構造を保ったままアップロードされます
3. 下の「Commit changes」ボタンを押して保存

> Gitの操作に慣れてきたら、GitHub Desktop（無料アプリ）を使うと2回目以降の更新がもっと楽になります。
> https://desktop.github.com/

### ステップ4：GitHub Pagesを有効にする
1. リポジトリの「Settings」タブを開く
2. 左メニューの「Pages」を開く
3. 「Build and deployment」→「Source」を **Deploy from a branch** に設定
4. Branch を **main**、フォルダを **/(root)** にして「Save」
5. 数十秒〜数分待つと、ページ上部に公開URLが表示されます
   - 例：`https://username.github.io/EMS-rules/`

### ステップ5：更新の反映
`content/*.md` を編集して「Commit changes」するたびに、自動で1〜3分ほどでサイトに反映されます。
特別な作業（ビルドやデプロイ操作）は一切不要です。

## 5. 独自ドメインを使いたい場合（フリードメインでの継続）

1. お名前.com やFreenomなどでドメインを取得（または既にお持ちのフリードメイン）
2. リポジトリの Settings → Pages → 「Custom domain」に取得したドメインを入力
3. ドメイン管理画面側で、GitHubが案内するIPアドレス（Aレコード）または
   `username.github.io` へのCNAMEレコードを設定
4. 反映まで数時間かかることがあります（DNSの伝播待ち）

`username.github.io/EMS-rules` のままで運用する場合はこの手順は不要です。

## 6. パソコンで動作確認する方法（アップロード前のテスト）

このサイトはページの中身を `content/*.md` から**あとから読み込む**仕組みのため、
`index.html` をダブルクリックしただけではブラウザのセキュリティ制限で正しく表示されないことがあります。
下記のどちらかの方法でローカルサーバーを立てて確認してください。

- **Python がある場合**：このフォルダで `python3 -m http.server 8000` を実行し、
  ブラウザで `http://localhost:8000` を開く
- **VS Codeを使う場合**：拡張機能「Live Server」を入れて `index.html` を右クリック→「Open with Live Server」

GitHub Pagesにアップロード後は、この手順は不要です（そのまま正しく表示されます）。
